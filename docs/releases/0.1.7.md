# Harbor 0.1.7

An update to Harbor 0.1.6. Switching tabs is smoother, Setup shows a permission as granted as soon as you grant it, cancelling in Ask really removes the item from Calendar or Reminders, and Harbor is more careful about what it says it did. It also closes several gaps found in an independent security audit of 0.1.6. Everything in [0.1.6](0.1.6.md) still applies.

## What's new in 0.1.7

### Smoother tabs

- **One glide between tabs.** Going from a short tab to a tall or wide one is now a single motion: the window grows first, then the panel opens into it.
- **The two-column button slides the panel** instead of snapping it to the new width.
- **With Reduce Motion on,** the panel cuts straight to its final size.

### Setup

- **A permission you grant shows as granted right away.** A slower, older check can no longer overwrite a newer answer. Harbor checks about once a second, and the notch's permission page looks again when you come back from System Settings.
- **Allowing Calendar or Reminders no longer reads "macOS didn't show its question".** For a moment after you allow either one, macOS can still report it as not yet asked. Harbor now trusts macOS's direct yes, so the row shows Allowed at once.
- **The notch stays open while macOS asks.** For a permission macOS asks about in its own dialog (Calendar, Reminders, Contacts, Notifications, Mail & Notes, Messages), the panel stays open and drops below the question until you answer. A permission granted in System Settings still tucks the panel away until you come back.
- **Screen Recording and Full Disk Access can still need Harbor to reopen.** That is macOS: it only applies those two after the app restarts.

### Cancelling in Ask

- **Cancel removes the item.** When you cancel an event in Calendar or a reminder in Reminders, Harbor removes that exact item (one occurrence, for a repeating event) and says "Cancelled" only after it has read back that the item is gone.
- **The approval card names what it will remove:** the item, its date and time, and its calendar or list.
- **Marking a reminder done** completes it in Reminders.
- **When Harbor cannot, it says so plainly.** That covers an invitation from someone else (decline it in Calendar), a read-only or subscribed calendar, and a whole repeating series.

### Texts

- **No false "Sent".** When Messages gives no sign that a text was delivered, Harbor says it was handed to Messages and that delivery is not confirmed.
- **No second copy.** If Messages reports an error after it has already queued the text, Harbor does not send it again.
- **A blocked or declined send gives a short reason.**

### Alarms and refused actions

- **Alarms understand more ways to say a time:** "7 a.m.", "at 6pm", "noon" and "midnight".
- **A refused action is no longer reported as done.** If a setting change, a clipboard action or a screenshot was refused, Harbor now says so.

### Security

These come from an independent audit of 0.1.6.

- **Only the Harbor app can talk to Harbor's background service.** Each launch makes a new key, and other programs on the Mac are refused.
- **No compiled-code cache in a folder any program can write to.** Starting Harbor takes about a second longer.
- **"Run in Terminal" asks first, inside the panel.** Pressing it turns the code block into a card that shows the whole script, with Cancel as the default. Nothing runs until you press "Run in Terminal" on that card.
- **The tool-server settings file is refused** if it is a link or if other users can write to it.

## For developers

- The phone gateway and scripts that call the running app's service are now refused by the new key. They need the key to work again.

## Requirements

- A Mac with Apple silicon (M1 or later). This download is for Apple silicon only.
- macOS 14 or newer. The built-in engine needs macOS 26.2 or newer; on macOS 14 to 26.1, Harbor needs another local engine running on the Mac (oMLX, Ollama, LM Studio or any OpenAI-compatible server).
- 16 GB of memory, and about 8 GB of free disk for the first model download.
- For Study material: your own OpenRouter or Gemini API key. For slides read page by page: a Gemini API key.
- For Gmail, Calendar and Drive: a Google account on the app's test-user list.

## Before you install

- **Harbor is not notarized.** macOS blocks the first open; allow it in System Settings > Privacy & Security > Open Anyway.
- **Quit any other assistant build first.** Harbor keeps its data in `~/.moe` and its service on the local port 8765 (the built-in engine uses 8000). Another build using the same folder or port will conflict with it.
- **Google sign-in is in testing mode.** Only Google accounts on the test-user list can sign in, Google shows an "unverified app" warning, and sign-ins expire after 7 days.
- **Slides page reading needs Study's own connector** set to the Gemini API with a Study key. Harbor's other cloud settings do not turn it on.

## What was and was not tested

- **Automated checks:** the release build ran Harbor's full Simulation QA on the tagged commit: all 656 checks passed, about 52,000 tests, none failed. The Intel build was put together from it and checked for x86_64 code only; it has not been run.
- **Tried by hand in the running app (Apple silicon preview):**
  - Switching between Ask, Brief, Day and Study and turning the two-column layout on and off. In the screenshots taken during each switch the panel never showed a cut-off edge; the smoothness of the motion itself was not measured.
  - Adding a test event in Ask, declining its cancel card (it stayed in Calendar, with a reason), then approving it (it left Calendar).
  - Adding a test reminder with a time and a title, then cancelling it in Ask (it left Reminders).
  - Asking Harbor's service for your day from another program on the Mac: it was refused.
  - Pressing "Run in Terminal" on a one-line script in the notch panel: the confirmation card opened inside the panel with the script shown. Cancel closed it and nothing ran. Confirming opened Terminal, which ran the script and printed its output.
- **Not tried by hand:** watching the Setup rows change as each permission is granted, sending a real text or email, alarms, Reduce Motion, the phone gateway, and the Intel build on an Intel Mac.

## Known issues

- **Google sign-in tokens are kept in a private file,** not in the Keychain.
- **A text that Messages marks Not Delivered** can still show only that it was handed to Messages. The red mark in the Messages app is the sign it did not go through.
- **A chat that was blocked by a failed text in an earlier build stays blocked.** Start a new chat.
- **Reduce Motion:** the four places where the panel could be briefly the wrong height should now cut straight to the final size. This has not been tried by hand.
- **A suggested block and a study block** can start at the same minute in Day.
- **If Calendar moves an event to a new time and re-issues it,** a study block can be booked twice.
- **A deck left reading** shows "Reading slides…" until Study is refreshed.
- **Lecture recordings are links only.** Harbor does not open or read them.
- **Teacher-added external links inside Modules are refused.**
- **Find's never-open rule is strict.** It also refuses study material whose title contains words like "midterm" or "final".
- **Find needs a course's Canvas address.** For a course without one, open the course page and press "Read again" first.
- **Recent fixes to cloud-key handling** are covered by tests that stand in for the Keychain. They have not been tried by hand with every key and macOS prompt.
- **Some features are untried in the running app:** reading email and Messages attachments, meeting notes and writing-style drafts.
- **Study reads Canvas only.** Other school sites are not supported. Treat Study as untested against school sites and Drive files you have not tried yourself.
- **Study has no Google account picker.** It uses the first connected account that allowed Drive access.
- **Forwarding through Apple Mail is not available yet.** Harbor says plainly that nothing was sent.
- **Reading the Mac's Mail and Messages** needs Full Disk Access in some cases.
- **Harbor does not update itself.**
- **The card for deleting a reminder is headed "changes your calendar".** The card below the heading names the reminder and its list correctly.
- **A schedule suggestion can appear at the top of Ask while an approval card is waiting** and push the approval card below the visible part of the chat. Scroll down to find it.
